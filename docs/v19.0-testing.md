# BookStack 19.0 testing

## Scope and dependency decision

Debian 13 Trixie does not provide a `bookstack` package. BookStack 19.0
therefore installs the official BookStack stable release v26.05.4 from
`https://source.bookstackapp.com/bookstack.git`. The build pins annotated tag
object `bb71d0f5e539cd853381125a86772813e73aee3d` and release commit
`cec78b1bcf096a74bf0a79fae3f884dc1d0803e4`. It verifies the tag signature
against upstream signing fingerprint
`98F8536570C9A3745BFA8BAF116094FE15AE65C0` before Composer runs.

PHP 8.4, MariaDB, Apache, Composer, Git, GnuPG and PHP extensions come from
signed Debian Trixie repositories. Composer installs the exact dependency
graph in BookStack's upstream `composer.lock`.

The supported updater is:

```sh
bookstack-update --check
bookstack-update --apply
```

The check resolves the official stable branch, requires it to have an
annotated release tag signed by the pinned upstream key, and does not change
the application. The apply mode refuses tracked local changes, enters Laravel
maintenance mode, fetches the already verified candidate, requires a
fast-forward source update, installs locked production dependencies, runs
database migrations and clears caches. Administrators should back up the
database and uploaded files before applying an update.

## Static and boundary checks

```sh
bash -n conf.d/main tests/v19.sh \
  overlay/usr/local/sbin/bookstack-update \
  overlay/usr/lib/inithooks/firstboot.d/20regen-bookstack-secrets \
  overlay/usr/lib/inithooks/firstboot.d/40bookstack
python3 -m py_compile overlay/usr/lib/inithooks/bin/bookstack.py
git diff --check
```

Normal firstboot with an unqualified `APP_DOMAIN=localhost` exercises the
noninteractive HTTPS default. Runtime tests additionally prove that instance
state survives at the HTTP and database boundaries, that the scheduler runs
under the intended service identity, and that update checks do not mutate the
installed source or Debian packages.

## Known limitation

Docker runtime validation does not exercise the installer, appliance kernel,
bootloader or physical hardware. BookStack adds no appliance-specific behavior
at those boundaries, so the validated Core 19 baseline supplies inherited
evidence.

## Deferred issues

- BookStack v26.05.4 currently defines no application-specific events in its
  Laravel scheduler. The cron integration and scheduler command are active so
  upstream can add scheduled maintenance without another appliance change.
- The focused content round trip covers the default WYSIWYG path. Markdown,
  attachments, diagrams, external authentication and outbound delivery require
  optional configuration and are outside the primary appliance flow.
